# Salut Sense — SMM / контент-пайплайн

Производство контента для Instagram Salut Sense и передача готового материала в
монтаж. Цепочка состоит из четырёх шагов, и на каждом — разный исполнитель.

## Цепочка (4 шага)

1. **Стратегия** — субагент `smm-scriptwriter`, режим «Стратег»: контент-план,
   темы, идеи под аудиторию и рубрики. Ничего не пишется в файлы как готовый
   контент — это обсуждение и выбор направления с пользователем.
2. **Контент-креатор** — тот же субагент, режим «Сценарист»: полные сценарии
   рилсов / постов / каруселей / сторис с раскадровкой и текстами. Результат —
   файл(ы) в `content/scripts/` со `status: draft`.
3. **Согласование** — ведёт **только эта (главная) сессия**, не субагент.
4. **ТЗ для монтажёра** — после утверждения эта сессия сама собирает финальный
   пакет: сценарий + реальные файлы материалов из проекта (см. ниже), и только
   потом передаёт его в монтажный skill/сессию.

## Жёсткое правило: approve-gate держит главная сессия

Менять статус с `draft` на `approved` может только эта сессия — и только после
явного слова пользователя: «утверждаю», «approved», «берём», «этот оставляем»,
«сценарий согласован», либо прямая команда передать в монтаж.

«Нравится», «хорошо», обсуждение деталей, молчание — это НЕ утверждение.
Субагент `smm-scriptwriter` никогда не пишет `status: approved` сам — только
`draft`. Если неясно, утверждён вариант или нет — спросить прямо, не считать
по умолчанию.

После `approved` финальный текст сценария (`## Script` / `## Screens` /
`## Slides` — в зависимости от формата) менять нельзя ни этой сессии, ни
субагенту. Технические детали брифа (shot list, AI-промпты, список файлов) —
можно дополнять, смысл и текст утверждённого — нет. Если для монтажа кажется
необходимым что-то в тексте изменить — сообщить пользователю отдельно и
запросить согласование, не менять молча.

## Где что лежит

- `content/scripts/` — сценарии, один файл на единицу контента:
  `SS-XXX-краткое-имя.md`. Статус — в frontmatter
  (`status: draft/approved/rejected`).
- `content/knowledge/` — референсы бренда: транскрипции Лутаевой и Бездаря,
  визуальные референсы, описания и рендеры проектов (Aravita, Zanzibar, Bloom).
  Перед сценарием по конкретному проекту — читать файл, не полагаться на общие
  представления.
- `content/footage/` — сырой материал (видео/фото) для монтажа.
- `content/briefs/` — финальные ТЗ для монтажёра, один файл на утверждённую
  единицу контента: `SS-XXX-brief.md`. Создаёт эта сессия на шаге 4.

## Шаг 4 подробно: как собирается ТЗ для монтажёра

Как только пользователь утвердил сценарий:

1. Изменить `status: draft` → `status: approved` в файле сценария.
2. Определить, о каком проекте/материале идёт речь (по названию в сценарии —
   Aravita / Zanzibar / Bloom / другое), и найти в `content/knowledge/` и
   `content/footage/` реально существующие файлы, которые нужны для этого
   ролика: рендеры, референсы, отснятый материал. Использовать Glob/Grep — не
   придумывать пути и не полагаться на память, только реально найденные файлы.
3. Собрать `content/briefs/SS-XXX-brief.md` по структуре:

   ```
   ---
   status: approved
   source_script: content/scripts/SS-XXX-....md
   footage_dir: content/footage/SS-XXX/
   ---

   ## Final content
   <текст сценария/сторис/поста без изменений — то, что утвердил пользователь>

   ## Shot list / Screens / Slides
   <из сценария — раскадровка, тип каждого кадра, тайминги>

   ## Filming checklist
   <список того, что пользователь должен записать сам, с ТОЧНЫМИ именами файлов:
   SS-XXX_SHOT01_live.mp4 — кадр 1: <что в кадре, что говорит, откуда снято>
   SS-XXX_SHOT04_live.mp4 — кадр 4: <...>
   Только кадры типа [живая съёмка]. Кадры из рендеров/архива/ИИ сюда не входят —
   их закрывает монтажёр из Source files и AI prompts.>

   ## Editing notes
   <темп, склейки, звук, музыка, субтитры>

   ## AI prompts
   <если есть ИИ-кадры — промпты, движение камеры, свет, 9:16>

   ## Source files
   <явный список путей к реально найденным файлам — рендеры, референсы,
   архивный материал; без списка — не передавать бриф дальше>
   ```

4. Создать пустую папку `content/footage/SS-XXX/` — туда пользователь загрузит
   свои записи, названные по Filming checklist.
5. Показать пользователю Filming checklist — коротко: какие файлы записать и
   как назвать. Это его единственная ручная часть.

## Монтаж без участия пользователя

Когда пользователь загрузил записи и говорит «монтируй SS-XXX» (или просто
«смонтируй» с очевидным контекстом):

1. Проверить `content/footage/SS-XXX/` против Filming checklist из брифа. Все
   ли файлы на месте, совпадают ли имена. Если чего-то не хватает — назвать
   недостающие файлы пользователю и остановиться, не монтировать с дырами и не
   подменять отсутствующие кадры молча.
2. Если файлы названы не по конвенции, но очевидно, что есть что (например,
   один файл в папке при одном кадре в чеклисте) — переименовать по конвенции
   и продолжить, упомянув об этом.
3. Передать монтажному skill/сессии путь `content/briefs/SS-XXX-brief.md` —
   весь контекст монтажа (раскадровка, тайминги, где какой файл) уже внутри
   брифа. Ничего не пересказывать вручную и не досочинять от себя.

Монтажёр работает только по брифу: раскадровка говорит, какой файл в какой
кадр, Editing notes — как клеить. Вопросы по существу (не хватает материала,
кадр не бьётся с таймингом) — поднимать пользователю, а не решать молча.

## Делегирование

Идеи/контент-план/темы и полные сценарии — делегировать субагенту
`smm-scriptwriter`. Согласование, смену статуса и сборку брифа для монтажа —
всегда выполняет эта сессия сама, не субагент.
